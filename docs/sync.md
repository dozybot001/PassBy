# PassBy 局域网同步（第 1 版，设计）

状态：2026-11-15 设计，还没有写联网代码。按和安全组的约定，联网的改动先给它看设计，它同意后才动手。

## 1. 由来和范围

创始人 11-15 在 PassBy 开发会话定：

- 「其实一直有一个隐秘的痛点，多端同步」「我想做局域网的多端同步」。
- 「之前不做网页考虑的是同步不好做的问题，如果做局域网同步就没有这个前提了。我们支持手机同步、手机-电脑同步。浏览器不能做同步吗，调研一下。」这句收回了当天早些时候「PassBy 网页端不做了」：网页版在有同步的前提下恢复。
- 看完调研结论后：「可以，你直接推进到底」。

做什么：

- **手机和手机**（安卓、iPhone 任意组合）在同一个局域网里双向同步。
- **手机和电脑**：电脑上是 passby.tenonai.cn 的网页，连到手机，查看、搜索、复制、新建、修改、删除，改动当场写回手机。网页不登录，我们没有服务端接口，浏览器里不留密码本。

不做什么：账号、我们的服务器、云端中转、后台常驻、自动发现设备、跨网络（不在同一个局域网）同步。

和原来的定位一致：没有账号，不经过我们的服务器。数据只在用户自己的两台设备之间走。

## 2. 调研结论：浏览器能不能连局域网里的手机

浏览器页面不能监听端口，只能主动连接。所以手机当服务端（下称「主机」），另一台手机或网页当「来宾」去连。

- **Chrome、Edge 142 起可以**：有「本地网络」权限（Local Network Access）。https 页面第一次请求局域网地址时弹一次询问，用户允许后放行；目标是私有 IP 字面量时，`http://` 请求不算混合内容。11-15 在 Chrome 157 上查到 `local-network` 权限状态是 `prompt`；在不能授权的内置浏览器（Chromium 156，状态 `denied`）里，从 passby.tenonai.cn 的页面请求这台 Mac 局域网地址上的临时服务被拦下。用户点允许之后的连通没有实测（弹窗只能本人点），按官方文档是通的。
- **Firefox**：Mozilla 说从 151 起逐步推出同类权限，要实测。
- **Safari**：没找到它支持这项权限的官方说法，旧的兼容性测试里 https 页面请求局域网 http 是失败的；没有实测。页面上要写明用 Chrome 或 Edge。
- 不走的两条路：
  - 手机直接把网页发给电脑（电脑打开 `http://192.168…`）：不是安全上下文，浏览器不提供 `crypto.subtle`，没法只用系统自带的加密。
  - WebRTC：手机端要带一整套第三方库，还要一台牵线的服务器。

资料：Chrome 的 [Local Network Access 指南](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access) 和[公告](https://developer.chrome.com/blog/local-network-access)、[WICG 规范](https://wicg.github.io/local-network-access/)、Mozilla 的[说明](https://support.mozilla.org/en-US/kb/control-personal-device-local-network-permissions-firefox)。

## 3. 用起来是什么样

1. 在一台手机上打开「设置 › 同步」，点「让别的设备连过来」。页面显示两样东西：地址（如 `10.91.92.79:52814`）和配对码（12 位，分三组，如 `AB3D-9KXM-P2QW`）。这台手机就是主机；页面开着才能连，关掉就断。
2. 在另一台手机上打开「设置 › 同步 › 连到另一台手机」，或在电脑的 Chrome、Edge 里打开网页，输入地址和配对码。
3. 手机和手机：连上后各显示一次结果（新增、更新、删除、冲突各几条），完成。
4. 网页：连上后显示密码本，可以查看、搜索、复制和编辑；每次保存当场和手机同步一次。关掉网页或手机上的同步页面，网页里的内容清掉。
5. 配对码每次打开同步页面都换新的，用完就作废。没有「记住这台设备」，第 1 版每次都要输配对码。

**电脑上不想每次手输地址**（创始人 11-15：「电脑端每次要手输一次手机显示的地址。这个体验不好，有什么方案」）。浏览器发现不了局域网里的设备，也不能被手机连，所以做三件事把输入减到最少：

- **地址尽量不变**：每部手机第一次用同步时随机定一个端口，以后一直用它（存在本机）。家里和办公室的路由器一般给同一部手机发同一个 IP，所以地址多数时候不变。
- **网页记住上次的地址，打开就先试它**：localStorage 里只记地址。手机上的同步页面开着时，网页直接出现「输入配对码」，不用再输地址；连不上才让改地址。
- **第一次用「发到电脑」代替手输**：手机的同步页面有一个分享按钮，分享一条链接 `https://passby.tenonai.cn/app/#10.91.92.79:52814`，用任意方式发到电脑（隔空投送、微信文件传输助手、邮件）点开，地址就填好了。地址放在 `#` 后面，不会发给我们的服务器；链接里不带配对码。
- 之后可以再做的（不在第 1 版）：「记住这台电脑」，网页在浏览器里存一把不能导出的钥匙，以后连配对码也不用输。它要在浏览器里落一把钥匙，和「网页不落盘」有出入，等安全组看过再定。
- 不做的：让网页扫描整个网段找手机（要发几百个请求，像是在扫网）；靠 `.local` 名字找手机（安卓的 mDNS 主机名是随机的，各系统解析也不一致）；用我们的服务器帮两边对上（又有了服务器）。

## 4. 数据怎么变

两部手机上的密码本文件各加三样（网页只在内存里有）：

- 每个条目、每个文件夹加 `updatedAt`（毫秒时间戳，最后一次修改）和 `dirty`（上次同步成功以后改过没有）。
- `tombstones`：被删掉的条目和文件夹留一个墓碑 `{id, kind, deletedAt, dirty}`，这样对方才分得清「你删了」和「你本来就没有」。墓碑留 400 天。
- 升级旧文件：`updatedAt` 填升级那一刻，`dirty` 为 true（第一次同步时都算改过）。

不变的：导出文件格式（第 1 版，`docs/export-format.md`）不带这些字段；导入时 `updatedAt` 取当时、`dirty` 为 true。「最近删除」、草稿、上次导出日期照旧只在本机。

## 5. 合并规则（三端一致）

主机算合并，结果两边都采用。输入是两边各自的全部条目、文件夹和墓碑。对每个 `id`：

| 情况 | 结果 |
| --- | --- |
| 只有一边有（条目、文件夹或墓碑） | 照那一边的 |
| 两边都有，内容相同 | 不变 |
| 两边不同，只有一边 `dirty` | 取 `dirty` 的那边（包括删除） |
| 两边不同，都不 `dirty`（三台以上设备转着同步时会出现） | 取时间晚的（`updatedAt` 或 `deletedAt`）；一样晚取主机的 |
| 两边都 `dirty`，都是条目 | 时间晚的留作这一条；另一份换新 `id` 另存一条，标题后加「（冲突副本）」/「 (Conflict copy)」 |
| 两边都 `dirty`，一边是条目一边是墓碑 | 留条目（改动胜过删除，免得丢密码） |
| 两边都 `dirty`，都是文件夹 | 取时间晚的名字，不留副本 |
| 两边都是墓碑 | 取时间晚的 |

合并以后：

- 条目指向的文件夹如果不在结果里，改成未分组。
- 结果里所有 `dirty` 清掉。主机在发出回复后清；来宾在收到并写好后清。来宾没收到回复时它的 `dirty` 还在，下次同步照常处理。
- 因为同步而从本机消失的条目，进本机的「最近删除」，留 30 天。
- 「内容相同」对条目指标题、账户、密码、备注、文件夹五项都相同；对文件夹指名字相同。

时间只用来在「都改了」或「都没标记」时挑一个，不同设备的时钟差一点不会丢数据：两边都改过的一定两份都留下。

来宾是网页时没有本地数据：第一次交换发一个空状态，得到主机的全部内容；之后每次保存，把内存里的全部内容（改过的标 `dirty`，删掉的带墓碑）再交换一次。

参考实现和测试向量照 `export-format` 的做法：`scripts/sync-format.mjs` 和 `docs/sync-vectors.json`，三端都要通过。

## 6. 协议

### 6.1 连接

- 主机在显示的那个局域网 IPv4 地址上监听一个端口（49152–65535 里随机选一次，存在本机以后一直用；被占用时临时换一个并在页面上显示），只在同步页面开着时监听；页面关掉、应用离开前台、10 分钟没有请求，或配对码错了 5 次，就停止监听并作废配对码。
- 传输是普通的 HTTP/1.1（不是 HTTPS：局域网地址拿不到浏览器认的证书，自签证书浏览器不认）。**所有内容在应用层加密并认证**，HTTP 只是信封。
- 手机这边不用系统的 HTTP 库：主机用套接字自己读写 HTTP（安卓 `ServerSocket`，iPhone `NWListener`），来宾手机也用套接字（`Socket`、`NWConnection`），所以不受「禁止明文 HTTP」的系统设置影响，也不用为此放开它。网页用 `fetch`。
- 请求大小上限 8 MB，读写超时 15 秒，一次只处理一个连接。请求行、头、长度不合规的直接断开。
- 给浏览器的头：`Access-Control-Allow-Origin: https://passby.tenonai.cn`（只这一个来源），`Access-Control-Allow-Methods: POST`，`Access-Control-Allow-Headers: content-type`，`Cache-Control: no-store`；`OPTIONS` 预检回 204。

### 6.2 两个请求

`POST /passby-sync/v1/begin`，请求体为空。回 16 字节随机数 `hostNonce`。每个 `hostNonce` 只能用来开始一个会话，60 秒内有效。

`POST /passby-sync/v1/exchange`，请求体是二进制：

```
hostNonce(16) | guestNonce(16) | counter(8，大端) | 密文 | 标签(16)
```

回复体：`counter(8) | 密文 | 标签(16)`。

- 一个会话由 `(hostNonce, guestNonce)` 确定。来宾第一次交换时带自己新生成的 `guestNonce`，主机这时才派生密钥。
- 同一个会话可以交换多次（网页每次保存一次）。来宾的 `counter` 从 0 起每次加一，主机只接受比上一次大的；主机回复用同一个 `counter`。
- 解不开或认证不过：回 403，计一次失败。别的错误回 400；主机已经停止监听的回 410。回复体为空，不带任何说明。

### 6.3 密钥

```
code     = 配对码去掉横线和空白、转大写后的 12 个 ASCII 字符（Crockford Base32，60 位随机）
salt     = "PassBy sync v1" | hostNonce | guestNonce
master   = PBKDF2-HMAC-SHA256(code, salt, 600,000 次, 32 字节)
k_g2h    = HKDF-SHA256(master, salt 空, info "PassBy sync v1 guest to host", 32 字节)
k_h2g    = HKDF-SHA256(master, salt 空, info "PassBy sync v1 host to guest", 32 字节)
nonce    = 4 个零字节 | counter(8)
aad      = "PassBy sync v1" | hostNonce | guestNonce | 方向(1 字节：0 来宾到主机，1 主机到来宾) | counter(8)
加密     = AES-256-GCM(密钥按方向选, nonce, aad)
```

- 只用系统自带的加密：安卓 `javax.crypto`，iPhone CommonCrypto 加 CryptoKit，网页 WebCrypto。和导出文件同一套算法。
- 配对码用系统的安全随机数生成，每次打开同步页面换新的，不保存。
- 配对码输错 5 次主机就停，所以在线猜不动；抓到一次交换的人要离线猜 60 位的码，每猜一次要算 60 万次 PBKDF2。
- 两个方向各用一把密钥，计数器不回退，重放和调换方向都会认证失败。

### 6.4 明文

请求明文（UTF-8 的 JSON）：

```json
{
  "v": 1,
  "entries": [{ "id": "…", "title": "…", "account": "…", "password": "…", "notes": "…", "folderID": "…", "updatedAt": 1794700000000, "dirty": true }],
  "folders": [{ "id": "…", "name": "…", "updatedAt": 1794700000000, "dirty": false }],
  "tombstones": [{ "id": "…", "kind": "entry", "deletedAt": 1794700000000, "dirty": true }]
}
```

回复明文：

```json
{ "v": 1, "state": { "entries": […], "folders": […], "tombstones": […] }, "summary": { "added": 0, "updated": 0, "removed": 0, "conflicts": 0 } }
```

- `id` 是 UUID，大小写都认；同一类里不能重复；`folderID` 可以没有，有的话要指向 `folders` 里的一个。不符合的整份拒绝（回 400），什么都不改。
- `summary` 是从来宾的角度数的：它新增、更新、删掉了几条，留了几份冲突副本。主机在自己的页面上显示自己那一侧的数。
- `v` 比认识的大：回 400，页面提示「请更新 PassBy」。

## 7. 网页

- 静态页面，放在 passby.tenonai.cn 的 `/app/`。不登录，不向我们的服务器发任何东西。
- 只连用户输入的那个地址：必须是私有 IPv4 字面量（10/8、172.16/12、192.168/16）加端口，别的不连。
- 解开的内容只放在内存里：不写 IndexedDB、localStorage、sessionStorage，不用 service worker。只把上次连上的地址记在 localStorage 里；地址也可以从链接的 `#` 后面带进来（见第 3 节），带进来的同样要过私有地址的校验。离开窗口 5 分钟或关掉页面就清掉并断开。
- 条目内容当作不可信：只用 `textContent`，不用 `innerHTML`。
- 内容安全策略（只这个页面）：`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src http:; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; require-trusted-types-for 'script'`。`connect-src http:` 是因为 CSP 没法只写私有网段；页面自己只连校验过的私有地址。要不要这样放开请安全组定。
- 复制：浏览器不能让剪贴板自动过期，页面上写明，只在自己的电脑上用。
- 浏览器：页面检测到没有「本地网络」权限这回事时（Safari、旧版本），说明要用 Chrome 或 Edge。

## 8. 请安全组看的几处

1. 局域网里走明文 HTTP、内容在应用层用 AES-GCM 加密认证，这个做法行不行。
2. 12 位配对码（60 位）加 60 万次 PBKDF2，错 5 次即停，够不够；要不要更长。
3. 手机上自己写的最小 HTTP 服务端：请求大小、超时、单连接这些上限够不够，还要什么。
4. 网页的 `connect-src http:`，和 `Access-Control-Allow-Origin` 只给 passby.tenonai.cn。
5. 网页不落盘、5 分钟清内存这套，够不够；旧网页版在这个源上留下的 IndexedDB 数据（`passby-trusted-browser`）第一次打开时删掉。
6. 安卓要不要为监听端口加权限或前台服务（设计里不加：只在页面开着时监听）。iPhone 要加「本地网络」用途说明，系统会弹一次询问。

## 9. 对外说法和法律文本

应用会在局域网里收发数据，不上互联网，不经过我们的服务器。隐私政策、用户协议、关于页和官网那句要照实改，文字请法务组给；创始人定的口径是不替别人揽责、照实说。安卓和网页先上，iPhone 随它的版本一起。
