## 1. 做什么

功能和 iPhone 2.0 一致：

- 条目（标题、账号、密码、备注）、分组、搜索、密码生成器。
- 最近删除，保留 30 天。
- 点一行复制密码；复制后 60 秒清除，剪贴板带敏感标记。

- 中英文、深浅色、关于页、隐私政策和用户协议入口；配色和图标用黑白灰（创始人 11-15 决定换回，见 `docs/local-notebook.md` 第 7 节；之前用过方案 A 牛皮纸）。

技术选择：Kotlin 加 Jetpack Compose，原生，最低 Android 8.0（API 26）。

## 4. 设计

### 4.1 本机存储

- 一个 JSON 文件：`files/notebook/notebook.json`，在 App 私有目录里，由系统的文件级加密保护。不另加 App 自己的密钥，理由和 iPhone 相同：安卓密钥库里的密钥不随备份和换机走，加了以后新手机上打不开。
- 条目、分组、最近删除、没保存完的草稿、上次导出时间、门的开关都在这一个文件里。
- 写入：先把新内容写到另一个文件并读回核对，把被替换的那份另存为 `notebook.json.previous`，再把新文件改名到位。任何时刻当前文件都是完整的，并且总有上一份可以回退。
- 当前文件读不出、上一份读得出：用上一份，把读不出的那份改名留着（`notebook.json.unreadable`），不删。
- 两份都读不出，或者文件是更新版本的 PassBy 写的：不显示空本子，文件原样不动，提示原因。
- App 不自动删用户的数据。只有两处会让条目消失：用户自己在最近删除里点「立即删除」；最近删除满 30 天。

### 4.2 导出和导入

- 格式照 `docs/export-format.md`。PBKDF2 和 HKDF 在 `Mac`（`HmacSHA256`）上自己算，不用 `PBEKeySpec`；加密用 `Cipher` 的 `AES/GCM/NoPadding`。
- 口令首尾空白和导出码里的空白、横线，用格式文档列的字符集判断，不用 Kotlin 的 `trim()`。
- JSON 用自己写的严格解析（`core/Json.kt`），不带 JSON 库：系统自带的 `org.json` 会接受注释、不带引号的词这类不是 JSON 的内容，各端对同一个文件的判断会不一样。
- 单元测试直接读 `docs/export-vectors.json`，不复制。
- 导出时间只精确到秒。导入时除了格式文档写的 `2026-11-14T12:00:00Z`，也认带毫秒、带时区偏移、不带时区和只有日期的写法，因为参考实现都认。
- 合并和替换照 `docs/export-format.md` 第 7 节，和 iPhone 同一套（11-14 和「PassBy · 开发」对齐，PassBy 1329b9c）。合并只增不减；替换把本机原有的条目全部放进最近删除，不直接删。
- 导出码旁边显示二维码，内容是带横线的 23 个字符。App 里不做扫码：导入时手动输入或粘贴，所以不申请相机权限，也不带扫码库。

### 4.3 门

- 用 `androidx.biometric`：指纹或人脸，没有就用锁屏密码（`BIOMETRIC_WEAK` 加 `DEVICE_CREDENTIAL`）。App 只拿到验证成功或失败。
- 冷启动要验证；离开满 5 分钟，回来再验证（按系统开机后的计时算，改系统时间不影响）。默认开，在设置里可以关，关的时候要先验证一次。
- 锁着的时候，界面里只有锁屏页，密码本的内容不在界面树里。
- 手机没有设锁屏时（和 iPhone 一样，`docs/local-notebook.md` 第 3 节）：不拦，直接进列表。第一次打开提示一次：没有锁屏时手机的文件加密起不到保护作用，建议设锁屏密码；设置里门的开关旁写明「这台手机没有设锁屏」。

### 4.4 剪贴板和截屏

- 复制时带敏感标记（Android 13 起系统的复制预览不显示内容）。
- 60 秒后清除，有两道：App 自己的计时器；进程被系统停掉时靠一个不精确的闹钟（不需要权限）。App 在前台时能看到剪贴板是不是已经换成了别的内容，换了就不清；在后台看不到，只能清掉。
- 整个窗口设 `FLAG_SECURE`：不能截屏和录屏，多任务界面不显示内容。对话框和菜单继承这个设置。

### 4.5 系统备份

- 进备份的只有 `notebook.json` 和 `notebook.json.previous`。
- Android 12 及以上（`data_extraction_rules.xml`）：云端备份只在能端到端加密时做，也就是设了锁屏的手机；换机直传照常。
- Android 9 到 11（`full_backup_content.xml`）：同样的两个条件，用 `requireFlags` 写。
- Android 8.0 和 8.1：系统不能对备份做端到端加密，所以关掉系统备份，只能靠导出文件。
- 国行手机没有 Google 备份。各厂商的换机工具带不带得走，要真机验证；带不走的靠导出文件。

### 4.6 界面

## 5. 代码在哪

`android/app/src/main/kotlin/cn/tenonai/apps/passby/` 下分四块：

- `core/`：不依赖安卓的纯 Kotlin，单元测试直接在电脑上跑。见下表。
- `data/NotebookRepository.kt`：密码本在内存里的唯一一份，改动写进文件以后才显示。

`core/` 里的文件：

| 文件 | 内容 |
| --- | --- |
| `ExportSecret.kt` | 导出码和口令变成 PBKDF2 的输入字节；设口令的规则；生成导出码 |
| `ExportFile.kt` | 文件头、PBKDF2、HKDF、AES-GCM、导入的第 1–5 步检查 |
| `ExportPlaintext.kt` | 明文 JSON 的读写，导入的第 6–8 步检查 |
| `Json.kt` | 严格的 JSON 读写 |
| `Notebook.kt` | 条目、分组、最近删除、导出提醒 |
| `ImportMerge.kt` | 导入时的合并和替换 |
| `PasswordGenerator.kt` | 密码生成器，字符集和 iPhone 相同 |
| `NotebookStore.kt` | 本机文件的读写 |
| `Qr.kt` | 画导出码的二维码（只编码，不解码）；单元测试用 ZXing 解回来核对，ZXing 不进安装包 |

单元测试在 `android/app/src/test/`。测试里写的预期值，我用 `scripts/export-format.mjs` 这份参考实现逐条核对过（PBKDF2 和 HKDF 的公开测试值、`format` 的各种写法、字段检查、时间的各种写法）。安卓这边的测试本身还没跑过。

## 7. 构建、签名、发布

### 7.1 构建

要有 JDK 21 和 Android SDK（第 6 节）。SDK 的位置写在 `android/local.properties` 的 `sdk.dir` 里，这个文件不进 git。命令都在 `android/` 下跑：

| 命令 | 做什么 |
| --- | --- |
| `./gradlew :app:testDebugUnitTest` | 单元测试，含 `docs/export-vectors.json` 的全部向量 |
| `./gradlew :app:lintDebug` | lint |
| `./gradlew :app:assembleDebug` | 调试包 `app/build/outputs/apk/debug/app-debug.apk`。包名带 `.debug`，用调试密钥签，只用于测试 |

  `./gradlew --write-locks --write-verification-metadata sha256 :app:assembleDebug :app:assembleRelease :app:testDebugUnitTest :app:lintDebug`，把这几个文件的改动一起提交。

### 7.2 签名密钥

照产品规范 15.6 和安全组 11-14 的答复。

**密钥 2026-11-14 生成，当天做了备份并通过恢复演练。**

| 证书指纹 | |
| --- | --- |
| SHA-256 | `CDD81F2D2D37F3DB9C460C4F6E2186C900D6C68337589541284A683FD44A4984` |
| SHA-1 | `C72089B3F0110A4BC076DB4F4A8F5F7F91ADD62A` |
| MD5 | `0A929BF6B5671C3506650E1DDFB3A508` |

证书主体读回来是 `CN=PassBy, O="Changsha Tenon Artificial Intelligence Technology Co., Ltd.", L=Changsha, C=CN`。指纹不是秘密。

- 一把应用签名密钥：RSA 4096，有效期 30 年，PKCS12，别名 `passby`。放在仓库外的 `~/.tenon-keys/android/passby/passby-release.p12`，目录 0700、文件 0600。
- 证书主体用了就 30 年不变。公司英文名法务组 11-14 确认过，和邓白氏编码申请里的逐字一致。脚本生成后会读出证书里实际的主体，公司名不完整就报错。
- 密钥库的口令由脚本随机生成，直接存进登录钥匙串（服务 `tenon-android-signing`，账户 `passby`）。它不显示出来，不进文件、命令参数和日志。
- 生成：`scripts/create-signing-key.sh`。口令存进钥匙串以后 keytool 要是失败，重跑会被同名的钥匙串条目挡住：先确认没有密钥库文件，再删掉那个条目重跑，它没有保护过任何东西。
- 备份：`scripts/backup-signing-key.sh <第一处的文件夹> <第二处的文件夹>`。
  - 备份是一个 AES-256 加密的磁盘映像，里面有密钥库、密钥库的口令和写着三个指纹的说明。密钥库的口令直接写进挂载的映像，不经过普通磁盘。
  - 映像的口令由创始人在终端里输入，从键盘读，不经管道和参数，也不出现在任何会话里。开发机上不留它。
  - 脚本当场做恢复演练：重新打开映像，用里面的口令打开密钥库，核对证书的 SHA-256 指纹和登记的一致；再用里面的私钥签一份证书请求，验签通过，并且请求里的公钥就是证书里的公钥。只读证书不够，私钥坏了也读得出证书。之后每年演练一次。
  - 复制到两处以后，逐字节和原件比对。
- **备份做完并通过恢复演练之前，用这把密钥签的包不放 Releases，也不交给别人装。** 自己的模拟器和测试机可以装。
- 备份已做并通过恢复演练（2026-11-14）；备份的位置和口令的保管方式不写在公开仓库里，记在安全组的内部文档。演练的输出：「恢复演练通过：从备份打开密钥库，用里面的私钥签名并验签成功；证书 SHA-256 指纹是 CDD81F2D2D37F3DB9C460C4F6E2186C900D6C68337589541284A683FD44A4984，和登记的一致。」
- 备份脚本头两次没跑成，是脚本的错：变量名后面紧跟中文标点时，bash 把标点的第一个字节算进了变量名，报变量未定义后停下。改在 8dc602b，改完用一次性的测试密钥把整个脚本从头到尾跑通过。
- 登记：证书的 SHA-256 在 `android/release/signing-certificate.sha256`，发布脚本每次拿它核对；三个指纹见上表，SHA-256 另要写在支持页。
- 调试版用调试密钥，不碰正式密钥。
- 怀疑泄露：停止用它发布，告诉安全组（15.6.6）。

安全组 11-14 审过这几个脚本（审的是 9346db7），做法认可，提了三处修改，都改了：恢复演练要实际用私钥签一次并验签；发布脚本按名单逐项核对权限，不用关键词去排除；包在全部核对通过以后才得到正式的文件名，中途退出时删掉没核对完的文件。

三个脚本用到的命令，11-14 用一次性的测试密钥在临时目录里逐条试过，测试密钥已删：

- 临时的钥匙串文件里存取口令；带转义逗号的 `-dname`；`hdiutil` 的 `-stdinpass`；`apksigner` 的 `env:` 口令。
- 恢复演练的验签：正常的请求通过；签名被改过的、换了一把密钥的都被拒绝。系统自带的 openssl（LibreSSL）和 Homebrew 的 OpenSSL 3 都试了。
- 发布脚本的核对段落原样取出来跑：测试密钥签的正式构建在指纹对得上时通过；指纹不对、调试包、没签名的包都被拦下。

### 7.3 出正式包

### 9.1 设计（安全组 11-15 看过，同意，另加四处，见本节末尾）

版本 2.1.0，versionCode 2。

**联网的范围**

- 清单只加 `INTERNET` 一项，不加 `ACCESS_NETWORK_STATE`。`CheckPermissions` 和 `release.sh` 的名单各加这一项。
- 加 `network_security_config`：全局禁止明文；不信任用户安装的证书（正式版）。调试版另加 `debug-overrides` 信任用户证书，只为抓包核对发出的内容，不进正式包。
- 全应用只有一个类发网络请求（`system/AiClient.kt`），用系统的 `HttpsURLConnection`，不带任何网络库。加一项测试：主代码里除这个文件外，没有文件引用 `java.net` 的连接类。
- 这个类每次发请求前检查三件事，任何一件不成立就不建立连接：功能开着；地址以 `https://` 开头；用户刚在预览页点了「发送」（把那一次预览的内容原样交给它，它不自己取数据）。
- 不跟随重定向（`instanceFollowRedirects = false`），收到 3xx 当作失败。所以请求只到用户填的那一个主机。
- 不带 Cookie，不设自定义 User-Agent 以外的标识，不带设备、版本以外的任何信息；没有后台任务，没有重试循环，一次点击一次请求。超时 60 秒，返回体超过 1 MB 当作失败。
- 应用里没有日志输出，这个类也不记录请求、返回和 key。

**设置和 key 存在哪**

- 不放进 `notebook.json`。另有 `files/ai/settings.json`（开关、服务地址、模型名）和 `files/ai/key.bin`（API key 的密文）。
- key 用 Android Keystore 里的一把 AES-256-GCM 密钥加密（别名 `passby-ai-key`，不可导出，只用系统自带的实现）。明文 key 只在发请求时在内存里。
- 备份规则不动：进备份和换机的仍然只有 `notebook/notebook.json` 和它的副本，`ai/` 目录不在名单里。导出文件的内容由 `ExportPlaintext` 决定，只有条目和文件夹，和这两个文件无关。
- 关掉开关：当场删除 `key.bin`、Keystore 里的密钥和 `settings.json`，不需要另点删除。再打开要重新填。卸载时随私有目录一起删。
- 界面上 key 填完后不再显示，只显示「已保存」和「删除」。

**发出去什么，怎么保证**

- 组请求的是 `core/AiGrouping.kt` 里的一个纯函数 `request(titles: List<String>, folders: List<String>, model: String)`。它的参数只有字符串：标题和文件夹名。它拿不到 `Entry`，所以账户、密码、备注在类型上就进不来。
- 调用它的地方只有一处：从密码本取 `entries.map { it.title }` 和 `folders.map { it.name }`。条目的 `id` 不发，用这次请求里的序号（1、2、3…）代替，返回时按序号对回去。
- 标题为空的条目不发，直接归到「待明确」。
- 测试：造一批账户、密码、备注都是特征字符串的条目，走同一条路径组出请求体，断言这些字符串和条目 `id` 都不在里面。
- 请求体是 OpenAI 兼容的 `chat/completions`：`model`、固定的系统提示词、一条用户消息（JSON：`folders` 和带序号的 `titles`）、`temperature` 0、不流式。提示词是代码里的常量，不含任何用户内容。
- 默认预设 DeepSeek（地址和模型名写代码前对着它的文档核实）；「自定义」由用户填地址、模型名。境外服务商不预置。

**发之前给用户看**

- 每次点「开始分组」先到预览页，不发任何请求。页面顶部写：「只发送下面这些标题和文件夹名。账户、密码、备注不会发送。」下面列出这次要发的全部标题和文件夹名，再有一个「查看完整请求」，展开就是将要发出的请求体原文（key 不在请求体里，在请求头里，不显示）。
- 用户点「发送」才发。发的就是预览页显示的那一份，不重新生成。

**返回的内容怎么用**

- 返回只当数据：用应用自己的严格 JSON 解析器读，只认约定的格式（每个序号对应一个文件夹名、一个建议标题、是否不清楚）。序号对不上的、多出来的字段一律忽略；文件夹名和标题超过长度上限的那一项丢弃；格式不对就整体报错，什么都不改。返回里的文字只会显示在预览里或成为文件夹名、标题，不会被当作指令或链接。
- 结果页逐项列出：原标题 → 建议标题，原文件夹 → 建议文件夹。每项一个勾选框，可以全选或全不选。「待明确」单独列在一组，旁边有「改标题」。
- 用户点「应用」才改，一次保存：新建需要的文件夹（和现有文件夹同名的用现有的）、移动勾选的条目、改勾选的标题。不删条目，不删文件夹。条目总数前后相同，有测试。
- 应用后底部提示里有「撤销」，把这次改动的文件夹归属和标题恢复原样。
- 「待明确」是一个普通文件夹，中文叫「待明确」，英文叫「To clarify」。

**界面和说明**

- 设置里加一行「AI 分组」。进去是一页说明和一个开关，默认关。关着时这一页以外没有任何入口。
- 打开开关时弹确认，写明：发什么（标题和文件夹名），不发什么（账户、密码、备注），发给谁（你填的服务商），内容由该服务商按它的隐私政策处理、可能被它保存，选境外服务商时内容发往境外，API key 只加密存在这台手机上。用户点「打开」才生效。
- 「只拿到标题」这句话出现在三处：AI 分组页的开头、打开时的确认、每次发送前的预览页。
- 关于页和导出页里「不联网」的句子改成「默认不联网，只有你打开 AI 分组时才联网」；创始人定稿的那句要等他点头。

**安全组 11-15 加的四处（都做了）**

- API key 和主机绑定：保存 key 时记下主机名；改地址换了主机，旧 key 当场删掉；发之前核对主机一致。
- 出错时不显示服务器的返回体，只显示状态码和自己的一句话；返回体不记录、不进剪贴板。
- 建议的标题和文件夹名去掉控制字符和换行、限制长度后才显示和保存。
- 验证记录要有抓包：关着时零流量、发送一次只有到所配主机 443 的一条连接、关掉后又是零。见 9.3。
- 它还确认：换机或恢复后密钥库里的密钥不在，`key.bin` 解不开时当作没填；预览页同样受 `FLAG_SECURE` 保护。

### 9.2 两端要一致的做法（安卓已做出来，iPhone 照这个做）

**请求**（`core/AiGrouping.kt` 的 `request`）

- `POST` 到用户填的接口地址，OpenAI 兼容的 `chat/completions`。请求头只有：`Content-Type: application/json`、`Accept: application/json`、`Authorization: Bearer <key>`、`User-Agent: PassBy-Android/<版本>`（iPhone 用 `PassBy-iOS/<版本>`；不用系统默认的，默认值带机型和系统版本）。
- 请求体的字段和顺序：`model`、`messages`（两条：`system` 是固定提示词，`user` 是下面的 JSON 字符串）、`temperature` 为 0、`stream` 为 false。不带 `response_format`，免得有的服务商不认。
- `user` 消息的内容是一个 JSON 字符串：`{"folders":["文件夹名",…],"titles":[{"n":1,"title":"标题"},…]}`。`n` 从 1 起，是这次请求里的序号，不是条目的 `id`。
- 标题为空白的条目不发。一次最多 500 个标题（`MAX_TITLES`），按密码本里的顺序取前 500 个，多出的这次不发，预览页会说明。
- 提示词是代码里的常量 `SYSTEM_PROMPT`，英文，原文照抄代码，两端逐字相同。它不含任何用户内容，也不含语言、机型之类的信息。

**返回**（`parse`）

- 取 `choices[0].message.content`，它应当是 JSON：`{"items":[{"n":1,"folder":"…","title":"…","unclear":false},…]}`。外面包了一层 Markdown 代码围栏的也接受，去掉围栏再读。
- 用应用自己的严格 JSON 解析器。取不到 `content`、不是 JSON、没有 `items` 数组：整体报错，什么都不改。
- 逐项：`n` 必须是 1 到所发标题数之间的整数，否则忽略；同一个 `n` 出现第二次的忽略；多余的字段忽略。
- `unclear` 为 true：这一条算「待明确」，不采用它的 `folder` 和 `title`。
- `folder` 和 `title` 先清理再用（`clean`）：去掉控制字符、换行、零宽字符和改变文字方向的字符，连续空白并成一个空格，去掉首尾空白；清理后为空，或文件夹名超过 40 个码点、标题超过 120 个码点，这一项丢弃（等于没有建议）。
- 返回里的文字只会显示在结果页，或成为文件夹名、标题。不当作链接，不当作指令。

**结果怎么显示和应用**

- 只列出有改动的条目：建议的文件夹和现在的不同，或建议的标题和现在的不同。都相同的不列。
- 「待明确」的条目建议放进名为「待明确」（英文界面「To clarify」）的普通文件夹，不改标题；旁边有「改标题」，点了进编辑页。没发出去的空白标题条目也列在这一组。
- 每条一个勾选框，同时管这一条的改名和移动；默认全选，有「全选」「全不选」。点「应用 N 条」才改。
- 应用（`apply`）：一次保存。建议的文件夹和现有文件夹同名（NFC 后逐字相同）就用现有的，否则新建；条目改标题、改所属文件夹。不新增、不删除条目，不删除文件夹；账户、密码、备注不动。
- 应用后提示「已应用 N 条建议」，带「撤销」（`undo`）：把这次改过的条目的标题和文件夹恢复原样（条目还在的话），这次新建的文件夹如果已经空了就去掉。其间别的改动不受影响。

**服务商、设置和 key**

- 预置只有 DeepSeek：地址 `https://api.deepseek.com/chat/completions`，模型名 `deepseek-flash`（2026-11-15 对着 api-docs.deepseek.com 核实）。用户可以改成任何地址和模型名，有「恢复 DeepSeek 默认」。
- 地址必须是 `https://`，要有主机名，不能带用户名密码和 `#` 片段（`endpoint`）。不合格时不能保存，也不会发。
- 开关默认关。打开要过一次确认（写明联网、发什么、发给谁、key 存在哪）。打开时写入默认的 DeepSeek 地址和模型名。
- 设置（地址、模型名）和 key 不放进密码本文件，不进系统备份，不进导出文件。安卓放在 `files/ai/`；iPhone 对应的做法是放钥匙串，并且不随备份迁移到别的设备。
- key 只接受可见 ASCII（0x21 到 0x7E），首尾空白去掉，最长 512 个字符；带空格、换行、中文的不保存并提示（`apiKey`）。
- key 用系统密钥库里不可导出的密钥加密（安卓：Keystore 的 AES-256-GCM），密文里绑定保存时的「主机名:端口」（没写端口算 443）。读 key 时不一致就不给；改地址换了主机或端口，保存时当场删掉旧 key，要重新填。解不开的 key（换机、恢复备份之后）当作没填并删掉。
- key 保存后界面上不再显示，只有「已保存」和「删除」。关掉开关：当场删 key、密钥库里的密钥和设置。

**联网、失败和超时**（`system/AiClient.kt`）

- 全应用只有这一个类能发起连接，有测试检查别的源文件不引用连接类。
- 每次发送前检查：开关开着、地址合格、有这个主机的 key；任何一条不成立就不建立连接。要发的请求体是预览页显示的那一份，原样交过来。
- 不跟随重定向（3xx 当失败），不带 Cookie，不用缓存，不重试，没有后台任务。连接超时 20 秒，读取超时 60 秒，返回体超过 1 MB 当失败。
- 状态码不是 2xx 时不读返回体。任何情况下返回体都不显示、不记录、不进剪贴板。
- 发请求时任何意外的错误都转成「连不上」，不带出系统的错误原文（原文里可能有请求头，也就是 key），不让应用崩溃。
- 给用户看的只有自己写的一句话：地址不对、没有可用的 key（这两种写明「没有发送任何内容」）、连不上、超时、服务商要求跳转（带状态码）、服务商拒绝了 key（401、403）、其他错误（带状态码）、回复不是约定的格式（「没有改动任何内容」）。

**界面文案**

- 中英文都在 `res/values-zh/strings.xml` 和 `res/values/strings.xml` 里以 `ai_` 开头的条目，iPhone 照这些写，平台名词各按平台。
- 三处固定出现的两句：「AI 只拿到标题和文件夹名。」「账户、密码、备注这三栏不会发送。每次发送前，你都能看到要发出去的全部内容。」（法务组 11-15 定稿，不写「没有办法被发送」。）位置：AI 分组页开头、发送前的预览页开头；打开时的确认框里另有同样意思的一句。
- 预览页第一句：「下面这些文字会发给你配置的服务商（主机名）。」然后是标题清单、文件夹清单、「查看完整请求」（展开是请求体原文）。
- 关于页的一句改成：「没有账号，不经过我们的服务器；密码本由手机保管，跟着手机自己的备份和换机走。App 默认不联网，只有你打开「AI 分组」这一个功能时才联网。」这是法务组给的写法，原句是创始人定稿的，要他点头。
