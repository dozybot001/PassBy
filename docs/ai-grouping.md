# PassBy AI 分组

iPhone 和安卓一致的做法。功能默认关闭，用户自己配置模型服务商和 API key；只发条目标题和文件夹名，账户、密码、备注不发。安卓代码在 `android/app/src/main/kotlin/cn/tenonai/apps/passby/core/AiGrouping.kt`、`system/AiClient.kt`，iPhone 在 `PassBy/Models/AiGrouping.swift`、`PassBy/Security/AiClient.swift`、`AiSettings.swift`、`PassBy/UI/AiViews.swift`。改这里的规则要两端一起改。

**请求**（安卓 `core/AiGrouping.kt` 的 `request`）

- `POST` 到用户填的接口地址，OpenAI 兼容的 `chat/completions`。请求头只有：`Content-Type: application/json`、`Accept: application/json`、`Authorization: Bearer <key>`、`User-Agent: PassBy-Android/<版本>`（iPhone 用 `PassBy-iOS/<版本>`；不用系统默认的，默认值带机型和系统版本）。
- 请求体的字段和顺序：`model`、`messages`（两条：`system` 是固定提示词，`user` 是下面的 JSON 字符串）、`temperature` 为 0、`stream` 为 true。不带 `response_format`，免得有的服务商不认。
- `user` 消息的内容是一个 JSON 字符串：`{"folders":["文件夹名",…],"titles":[{"n":1,"title":"标题"},…]}`。`n` 从 1 起，是这次请求里的序号，不是条目的 `id`。
- 标题为空白的条目不发。一次最多 500 个标题（`MAX_TITLES`），按密码本里的顺序取前 500 个，多出的这次不发，预览页会说明。
- 提示词是代码里的常量 `SYSTEM_PROMPT`，英文，原文照抄代码，两端逐字相同。它不含任何用户内容，也不含语言、机型之类的信息。

**返回**（`parse`）

- 取 `choices[0].message.content`，它应当是 JSON：`{"items":[{"n":1,"folder":"…","title":"…","unclear":false},…]}`。外面包了一层 Markdown 代码围栏的也接受，去掉围栏再读。
- 用应用自己的严格 JSON 解析器。取不到 `content`、不是 JSON、没有 `items` 数组：整体报错，什么都不改。
- 逐项：`n` 必须是 1 到所发标题数之间的整数，否则忽略；同一个 `n` 出现第二次的忽略；多余的字段忽略。
- `unclear` 为 true：这一条算「待明确」，不采用它的 `folder` 和 `title`。
- `folder` 和 `title` 先清理再用（`clean`）：去掉控制字符、换行、零宽字符和改变文字方向的字符，连续空白并成一个空格，去掉首尾空白；清理后为空，或文件夹名超过 40 个码点、标题超过 120 个码点，这一项丢弃（等于没有建议）。
- 返回里的文字只会显示在结果页，或成为文件夹名、标题。不当作链接，不当作指令。

**结果怎么显示和应用**

- 只列出有改动的条目：建议的文件夹和现在的不同，或建议的标题和现在的不同。都相同的不列。
- 「待明确」的条目建议放进名为「待明确」（英文界面「To clarify」）的普通文件夹，不改标题；旁边有「改标题」，点了进编辑页。没发出去的空白标题条目也列在这一组。
- 每条一个勾选框，同时管这一条的改名和移动；默认全选，有「全选」「全不选」。点「应用 N 条」才改。
- 应用（`apply`）：一次保存。建议的文件夹和现有文件夹同名（NFC 后逐字相同）就用现有的，否则新建；条目改标题、改所属文件夹。不新增、不删除条目，不删除文件夹；账户、密码、备注不动。
- 应用后提示「已应用 N 条建议」，带「撤销」（`undo`）：把这次改过的条目的标题和文件夹恢复原样（条目还在的话），这次新建的文件夹如果已经空了就去掉。其间别的改动不受影响。

**服务商、设置和 key**

- 预置只有 DeepSeek：地址 `https://api.deepseek.com/chat/completions`，模型名 `deepseek-flash`。用户可以改成任何地址和模型名，有「恢复 DeepSeek 默认」。
- 地址必须是 `https://`，要有主机名，不能带用户名密码和 `#` 片段（`endpoint`）。不合格时不能保存，也不会发。
- 开关默认关。打开要过一次确认（写明联网、发什么、发给谁、key 存在哪）。打开时写入默认的 DeepSeek 地址和模型名。
- 设置（地址、模型名）和 key 不放进密码本文件，不进系统备份，不进导出文件。安卓放在 `files/ai/`；iPhone 对应的做法是放钥匙串，并且不随备份迁移到别的设备。
- key 只接受可见 ASCII（0x21 到 0x7E），首尾空白去掉，最长 512 个字符；带空格、换行、中文的不保存并提示（`apiKey`）。
- key 用系统密钥库里不可导出的密钥加密（安卓：Keystore 的 AES-256-GCM），密文里绑定保存时的「主机名:端口」（没写端口算 443）。读 key 时不一致就不给；改地址换了主机或端口，保存时当场删掉旧 key，要重新填。解不开的 key（换机、恢复备份之后）当作没填并删掉。
- key 保存后界面上不再显示，只有「已保存」和「删除」。关掉开关：当场删 key、密钥库里的密钥和设置。

**联网、失败和超时**（安卓 `system/AiClient.kt`，iPhone `Security/AiClient.swift`）

- 除了同步，全应用只有这一个类能发起连接，有测试检查别的源文件不引用连接类。
- 每次发送前检查：开关开着、地址合格、有这个主机的 key；任何一条不成立就不建立连接。要发的请求体是预览页显示的那一份，原样交过来。
- 不跟随重定向（3xx 当失败），不带 Cookie，不用缓存，不重试，没有后台任务。连接超时 20 秒，读取超时 60 秒（流式时是两次数据之间最长等 60 秒），模型写的文字超过 40 万字符、或整个返回超过 8 MB 当失败。
- **流式接收**：
  - 请求头 `Accept: text/event-stream, application/json`。返回按行读：以 `data:` 开头的行是一个事件，`data: [DONE]` 表示结束；事件的 JSON 里取 `choices[0].delta.content` 接到已收到的文字后面，没有这个字段的事件（比如只有 `role`，或推理模型的 `reasoning_content`）不加东西；JSON 解析不了的事件跳过。空行、以 `:` 开头的注释行不管。
  - 服务商不理会 `stream`、直接回一整份 JSON 时也能读：没有出现过 `data:` 行，就把各行拼起来当一份文档，取 `choices[0].message.content`。
  - 按行读时不用 `readLine()`：自己按字符读，单行超过 1 MB 或累计超过 8 MB 就当失败，服务端发一行不带换行的数据不能把内存撑爆。iPhone 同样自己按字节读。
  - 拼出来的文字和不流式时的 `message.content` 一样处理（去掉代码围栏、解析 `items`，规则不变）。参考实现是 `AiGrouping.StreamReader` 和 `AiGrouping.parseContent`，测试在 `AiGroupingTest`。
  - 等待时页面显示：还没收到文字时「已发送，正在等模型开始回复…（N 秒）」；收到以后「模型正在回复：已收到 a / b 条建议（N 秒）」。a 是已收到文字里 `"n":` 出现的次数（只用来显示，不超过 b），b 是发出的标题数，秒数每秒加一。
  - 有「不等了」按钮：关掉连接，不改任何东西，不提示出错。
- 状态码不是 2xx 时不读返回体。任何情况下返回体都不显示、不记录、不进剪贴板。
- 发请求时任何意外的错误都转成「连不上」，不带出系统的错误原文（原文里可能有请求头，也就是 key），不让应用崩溃。
- 给用户看的只有自己写的一句话：地址不对、没有可用的 key（这两种写明「没有发送任何内容」）、连不上、超时、服务商要求跳转（带状态码）、服务商拒绝了 key（401、403）、其他错误（带状态码）、回复不是约定的格式（「没有改动任何内容」）。

**界面文案**

- 中英文以安卓 `res/values-zh/strings.xml`、`res/values/strings.xml` 里以 `ai_` 开头的条目为准，iPhone 用同样的意思，平台名词各按平台。
- 三处固定出现的两句：「AI 只拿到标题和文件夹名。」「账户、密码、备注这三栏不会发送。每次发送前，你都能看到要发出去的全部内容。」位置：AI 分组页开头、发送前的预览页开头；打开时的确认框里另有同样意思的一句。
- 预览页第一句：「下面这些文字会发给你配置的服务商（主机名）。」然后是标题清单、文件夹清单、「查看完整请求」（展开是请求体原文）。
